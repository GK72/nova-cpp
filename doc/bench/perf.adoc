== Hardware

Every module is measured on the same machine, a desktop running Manjaro Linux
natively (kernel 7.2, `amd-pstate` active, `balance_performance`), built with
GCC 16.2 in Release (`-O3`) without sanitizers.

== Running the benchmarks

----
BUILD_TYPE=Release SANITIZERS= ci/build.sh
BUILD_TYPE=Release ci/bench.sh [<module>...]
scripts/bench-report.py [<module>...]
----

`ci/bench.sh` runs every benchmark (or the given modules) with

 BENCHMARK_MIN_TIME=1s
 BENCHMARK_REPETITIONS=10
 BENCHMARK_OUT=doc/bench/bench-$MODULE.json
 BENCHMARK_OUT_FORMAT=json

and `scripts/bench-report.py` turns the JSON into the tables the pages include
(`doc/bench/results-$MODULE.adoc`). The JSON keeps every repetition.

== Reading the tables

Every scenario is repeated, and the tables summarize the repetitions:

Median time::
    CPU time per call in one thread. With several threads, it is the time one
    call takes in a thread while the others run, so contention shows here.
Std dev::
    The standard deviation of the repetitions.
CV::
    The coefficient of variation, std dev / mean: the spread relative to the
    time. Below about 1% the scenario is stable; a few percent means the
    number holds only to its first digit or two.
Median rate::
    The throughput of all threads together: bytes per second where the
    scenario reports processed bytes, otherwise calls per second from the
    wall-clock time.
